
State steps - implementation record
For the agent implementing or re-implementing this. Every change made to add state changes without cloning components. Written so it can be rebuilt from scratch against a clean index.html.
Files touched: index.html (all logic), css/chrome-precision.css (row styles), AGENTS.md (workflow docs), examples/rag-explainer.json (converted to the new model).
1. The problem this solves
Before: new state from this (seqVariantSel) made a structured Clone of the component, gave the clone a new id, and set clone.hides=[original.id] so the clone retired the original when it appeared.
That breaks in four ways, all caused by the new id:
1. Wires don't follow. renderEdges only draws an edge when both endpoints are compVisible. The original is hidden by the clone, so every edge into it stops drawing. You must hand-author a duplicate edge per wire per state. A node with
4 wires and 3 states = 12 hand-maintained edge copies. (examples/rag-explainer.json originally carried exactly this hack: two edges evdcx/evdc2 for one swap.)
2. Props diverge. Fix a typo on the original and the clone keeps the old text.
3. The sequence list fills with near-identical rows.
4. hides is O(n) id bookkeeping that dangles when the original is deleted (there is a defensive filter at the #seq-hides render site that exists only for this).
After: a state step is an ordinary entry in comps that draws nothing and instead patches another component's props-or an edge's settings from its position in the list onward. The target keeps its id, so wires, text and ports all follow.
{"id":"s1", "type": state", "target":"apil", "label":"traffic spike"," "anim":"pa-zoom", "animDur":" ,"seqHold":
"props":{},
"patch":"sub":"p99 2.4s", "accent":"#FFB000"}}
Why an entry in comps and not a states[] array on the component Because it inherits the entire existing sequence machinery for free: drag-reorder, Alt+1, Ctrl+D, seqJump, undo (snap () serialises comps), autosave, save/load, export, and the teleprompter. An at: <index> field on a states[] array would need re-indexing on every insert/reorder. Do not "improve" this into a nested array.
Two deliberate details
props: {} is required. The codebase probes c.props.stepped in -8 places that iterate comps (renderList, seqNext, seqPlay, mirrorCompToPopup, the REC reset loop...). An empty object makes every one of those safe with zero guards. Without it you get TypeError: Cannot read properties of undefined. __state is NOT in REGISTRY. PAL_ITEMS is built from Object.entries (REGISTRY), so staying out keeps it off the palette automatically. Every REGISTRY [c.type] lookup that could see one must therefore be guarded
